# Fovyn V1 UX and brand amendment

Locked: 30 August 2026  
Implementation status: **brand wording current; Forest-first Home deferred**

## 1. Working tagline

The working Fovyn tagline is:

> **Grow More Good Days.**

It replaces **Build More Good Days.** in future branding and UI.

The change is intentional: people grow Goals; Goals grow Trees; Trees grow the Forest; over time people Grow More Good Days.

The approved growing-F logo and wider visual identity do not change.

## 2. Finished V1 becomes Forest-first

Forest implementation still begins only after the rest of functional V1 is complete and stable. Once built, however, the live Forest becomes the primary visual identity of Home/Today rather than only a secondary destination behind an Enter Forest action.

Home must immediately show, according to real user state:

- the user's live Forest or Nursery
- relevant Goal Trees
- today's priorities and progress
- important Goal states
- immediate Quick Input

The practical Today interface lives over and around the Forest; it does not replace it.

## 3. Forest is representation, not navigation

Hard UX rule:

> Making the Forest more prominent must never make recording the user's life slower.

The Forest represents the user. It is not the navigation system.

- Quick Input remains immediately available.
- Training opens the Training module.
- Nutrition opens the Nutrition module.
- Track opens the tracking interface.
- Goals opens the Goals interface.
- History opens History.
- No action requires locating a Tree, traversing the Forest or waiting for animation.
- Deeper functions remain conventional dedicated interfaces.

## 4. Responsive composition

### Desktop / Mac

- Immersive live Forest may occupy most of the available canvas.
- Today's Focus, progress, recent activity and Quick Input use restrained translucent/overlay UI.
- Functional navigation remains direct and visible.
- Available space should be used intentionally, not as a stretched phone layout.

### Mobile

- Live Forest forms the visual hero/top of Home.
- Today's Focus and progress remain immediately accessible.
- Quick Input opens over the Forest as an overlay or bottom sheet.
- Detailed modules use conventional screens.

### Tablet

Adapt between the desktop and mobile models according to available space. Performance and usability outrank maximum environmental detail.

## 5. Non-blocking Forest reactions

A qualifying action may produce subtle live feedback:

- brief emphasis on the relevant Goal Tree
- subtle leaf movement
- slight lighting or water response
- understated growth response only when genuine growth occurs

Reactions must never block input, route changes or another action. There are no mandatory cinematics.

## 6. Real new-user state

Never show a new user an artificial mature Forest.

```text
Initial experience: Nursery
Goal created: Seed
Qualifying contributions: Sprout → Young Plant
Common Juniper: graduate to the correct Area
Later history: wider Forest progressively becomes relevant
```

Home itself develops visually from the user's real Goal and contribution history.

## 7. Implementation sequence

This amendment changes the finished V1 experience, not the immediate priority:

```text
Functional V1 complete and stable
→ Forest V1 renderer
→ Forest state integration
→ Forest-first Home integration
→ responsive optimisation
→ Forest Lab QA
→ V1 final polish
```
